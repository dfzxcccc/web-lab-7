# Лабораторна робота №7

## Мета роботи
Ознайомлення з методами захисту та санації введених даних, обробка помилкових запитів на стороні сервера (Backend Validation).

## Фрагмент коду валідації (`create.php`)
```php
$errors = [];
$title = "";
$description = "";
$priority = "Low";

if ($_SERVER['REQUEST_METHOD'] == 'POST') {
    $title = htmlspecialchars(trim($_POST['title']));
    $description = htmlspecialchars(trim($_POST['description']));
    $priority = $_POST['priority'];

    if (empty($title)) {
        $errors[] = "Поле Назва не може бути порожнім";
    }
    
    if (empty($description)) {
        $errors[] = "Поле Опис не може бути порожнім";
    }
}

## Відповіді на контрольні запитання

1. У чому принципова різниця між валідацією на фронтенді та на бекенді?
Фронтенд-валідація (за допомогою HTML-атрибутів чи JS) виконується прямо в браузері користувача для швидкості та комфорту. Бекенд-валідація (на PHP) виконується на сервері та є ключовим рівнем захисту, оскільки перевіряє всі вхідні дані незалежно від того, як саме і звідки вони були надіслані.

2. Чому серверна валідація є критично необхідною з точки зору безпеки? Хто і як може обійти HTML required?
Користувач може легко обійти атрибут required у браузері, змінивши код через DevTools або надіславши POST-запит напряму через сторонні програми (наприклад, Postman чи cURL). Без перевірки на сервері це призведе до збереження порожніх чи шкідливих даних у базі.

3. Що робить функція trim()? Яку проблему вона вирішує?
Функція trim() видаляє зайві пробіли на початку та в кінці введеного рядка. Вона вирішує проблему випадкових зайвих натискань пробілу користувачем (наприклад, на початку назви завдання).

4. Від чого захищає функція htmlspecialchars()? Наведіть приклад.
Функція захищає від XSS-атак, конвертуючи спеціальні символи HTML (таких як <, >) у безпечні сутності. Якщо користувач введе <script>alert('hack')</script>, браузер виведе це як звичайний текст, а не виконає шкідливий скрипт.

5. Що таке масив помилок (Error Bag) і чому краще збирати всі помилки, а не переривати виконання одразу?
Масив помилок — це звичайний масив, куди записуються всі знайдені під час перевірки помилки. Це зручніше, ніж зупиняти код на першій же помилці за допомогою die(), бо користувач бачить усі свої недоліки за один раз і може виправити форму повністю.
